# 实时削峰平滑（C）

每来一个采样立刻输出一个点（**O(1)**，不看未来、不搬窗口）。输出点连起来是一条没有尖峰的平滑曲线；真下落大约 **2～3 个点**就能跟上。

## 算法思路

### 为什么旧做法实时性差

上一版用「过去 17 点的 min 再 max」（因果开运算）削峰。要削掉大约 8 个点宽的周期尖峰，窗口必须比峰更宽，于是**真下落也会被窗口里还没出去的高点拖住**，大约晚 20 个点才动。后面再套双极点低通，延迟更大。这是用「空间窗口」换「削峰」，和低延迟是矛盾的。

### 新做法：用方向和持续时间区分尖峰，而不是用长窗口

尖峰和真变化的差别不在幅度，在**朝向和能持续多久**：

| 现象 | 特征 | 处理 |
|---|---|---|
| 周期尖峰 | 相对当前平滑值**向上**冲，大约 5～8 个点就回来 | 先不跟 |
| 真上升 | 同样向上，但一直停在高位超过 `hold` 个点 | 确认后快速跟上 |
| 真下落 | **向下**走 | **立刻跟** |
| 小抖动 | 幅度不超过 `margin` | 交给 SmoothDamp 收圆 |

实现上只保留当前输出 `y`、速度 `vel`、向上计数 `high_count`：

1. 若 `x > y + margin`：`high_count++`。未满 `hold` 时目标仍是 `y`（削峰）；满了则目标改成 `x`，并用较短的 smoothTime 追上。
2. 否则（含下落）：`high_count = 0`，目标就是 `x`。下落用更短的 smoothTime，所以 84→70 这种边沿 2～3 个点就能贴近。
3. `y` 用 **SmoothDamp**（临界阻尼二阶跟踪）去追目标。它保证相邻输出连续、有速度、不振荡，连起来就是光滑曲线，又比长窗口 EMA 快。

这样削 8 点宽的峰只需要「向上持续不满 7 点就不认」，**不必再等 17 点窗口滑过去**。计算上每次只是几次加减乘，没有环形缓冲。

### 参数

- `--radius` / `hold`（默认 7）：多宽的上冲算尖峰。再大的峰才削得掉，真上升会多等这几拍。
- `--sigma`（默认 3.5）：曲线有多圆。主要加在**向上**的 smoothTime 上；下落始终用短 smoothTime，所以加大 sigma 几乎不拖累下落。

### 和业务的关系

- 尖峰：不进输出，避免误触发。
- 真跌落：2～3 点级延迟，便于及时响应。
- 真上升：最多等 `hold` 点确认，然后快速追上，避免把斜坡当尖峰削掉。

## 实时嵌入

```c
#include "smooth.h"

PeakCutStream s;
peakcut_stream_init(&s, 7, 3.5f);

float y = peakcut_stream_update(&s, x);  /* 来一个 x，出一个 y */
```

## 命令行

```bash
make
./smooth                      # samples.txt 当实时流逐点处理
./smooth --live --csv         # stdin 来一个打一个
./smooth --radius 8 --sigma 4
./smooth --offline            # 整段批处理（会用未来点，只作对照）
./smooth --self-test
```
